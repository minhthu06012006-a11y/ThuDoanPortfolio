Project Overview

AirWatch Vietnam is a real-time air quality monitoring web platform that lets residents track PM2.5 levels in major cities and proactively report pollution hotspots in their own neighborhoods.

The project was carried out as part of the DREAMLAB team's Smart City research, with the web dashboard being entirely my responsibility — from UX research through to front-end development.

Problem Statement

Air pollution in Vietnam has reached alarming levels, yet residents lack a simple tool to monitor air quality in the specific area where they live.

"Environmental data exists — but it's locked away in specialist reports. People don't know whether it's safe to go outside today."

Design Process

1

Define & Research

Analyzed the urban environmental problem. Studied existing monitoring systems (IQAir, AQMS, AirVisual) to identify UX gaps that these platforms had not yet solved.

2

Information Architecture

Organized the information flow: Landing → Live Map → Report Submission → Data Insights. Every key action takes a maximum of 2–3 steps to complete.

3

Visual Design System

Built a navy/cyan color palette — psychologically associated with clean air, scientific rigor, and trustworthiness. AQI color-coding fully synced with WHO's international color standard.

4

Interaction Design

Designed an interactive map for location-based pollution reporting. Instant feedback: reports appear on the map immediately with no reload needed — creating a sense that every contribution has immediate value.

5

Develop & Optimize

Built with Next.js + Tailwind CSS. Handled performance with a cache-aside pattern on PostgreSQL, cutting API latency from 15–20 seconds down to under 4 seconds.

Color-coded AQI badges instead of raw numbers "AQI 152" is meaningless to the average person Instantly readable: red = dangerous
Map-centric layout Users care more about their own area than national-level figures Increased personalization and engagement
Streamlined 3-step report form Lowers the barrier for users to contribute data Applies Nudge Theory — reporting becomes a natural behavior
Auto-updates every 3 minutes Air quality data changes quickly and needs near real-time updates Accurate information at all times without manual reloads

Challenges & Solutions

⚡ Challenge 1 — API Latency

The IQAir API responded slowly, taking 15–20 seconds and causing serious frustration during page load.

→ Solution: Cache-aside pattern with PostgreSQL — data cached for 3 minutes, cutting response time to under 4 seconds while still keeping things near real-time.
⚡ Challenge 2 — Accessibility for all ages

A diverse user base ranging from students to the elderly — the interface needed to be instantly understandable for everyone, including colorblind users.

→ Solution: International-standard AQI color-coding plus clear text labels, so meaning doesn't rely on color alone. A minimalist layout kept cognitive load low.
⚡ Challenge 3 — Motivating user contribution

Users are often unwilling to spend time reporting if they don't see immediate value.

→ Solution: Reports appear on the map immediately after submission (no reload needed) — creating an instant feedback loop that applies Nudge Theory to encourage contribution behavior.

Learnings & Reflections

This project taught me that UX isn't just about a beautiful interface — it's about actually solving a real user problem. When designing for complex data like AQI and PM2.5, the biggest challenge was "translating" technical information into language ordinary people could understand and act on immediately.

On the technical side, handling performance myself (caching, API optimization) gave me a much clearer understanding of the relationship between design decisions and technical constraints — an important perspective when working in an interdisciplinary environment.

If I were to continue this project, I'd run real usability testing with users and add push notifications for when AQI crosses dangerous thresholds — a gap in the current solution.
